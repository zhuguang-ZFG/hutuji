## 接口与事务

- `hutuji.speed` 增加 `axis=x/y/z/xy`，默认 `xy` 兼容旧调用；`rate=0`（默认值）只读三轴，正整数只写选中轴。`status.speed.axis_control=true` 作为能力声明；portal 在单轴写入前核对它，避免旧固件忽略 axis 而误改 X/Y。
- 主事件循环只受理，worker 保留现有 busy/settled/授权/金表/同一连接闸。写入后逐项查询 `$110/$111/$112`，每条必须有本次参数行和 `ok`，选中轴读回值必须相等才发布 done；任何错误/超时关闭本次连接隔离迟到应答。
- Pipe 只缓存接收到的速度行及各轴报告序号，不增加自动探针、不把速度放回金表；`hutuji.status` 仍只发 `?`。
- `GET /api/settings/machine-speed?device_mac=…` 返回三轴读回值；POST 增加 axis，保留原 rate 接口。全程复用手机号、设备所有权与 token 自愈闸。确认结果须匹配 request_id、axis、目标值和实际读回；旧无 axis 接口保留兼容。
- 小程序三个滑块；初次进入读取实机参数，未读到前显示未读取并禁调；只提交拖动轴。成功更新三轴读回值，失败还原滑块；页面/登录/设备代次隔离迟到回包。
