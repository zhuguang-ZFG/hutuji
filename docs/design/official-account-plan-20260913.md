# 公众号引流方案（订阅号 · 2026-09-13 决策稿）

## 决策记录（2026-09-13 用户拍板）

1. **类型：订阅号（内容引流）**。定位是作品秀/教程内容阵地，不是售后通知面（售后通知继续走小程序订阅消息与 TG 运维面，两者不合并）。
2. **主体：与小程序同主体**。具体主体名以小程序后台「设置→基本信息」为准，注册前线下核对；同主体是小程序内 `official-account` 关注组件与 `wx.openOfficialAccountChat` 的前置条件。
3. **内容策略：仅显式授权作品可公开**。图库未加授权链之前，用户作品一律不上公众号；授权链建设属期 2 开发，默认关闭。
4. **本轮仅落决策文档**。注册、认证、命名查重、内容运营均为线下动作；授权字段与发布 worker 未开发。

厂商公众号「派曦科技」（knowledge-base.md 厂商信息节，官网 2026-08-22 采集）是硬件厂商的售后号，不复用、不并号。

## 微信规则依据（外部证据）

- 小程序 `official-account` 关注组件：展示的公众号需与小程序**同主体或关联主体**；扫码打开小程序时展示，同一小程序生命周期内展示一次（微信开放文档，访问 2026-09-13：https://developers.weixin.qq.com/miniprogram/dev/component/official-account.html ）。
- `wx.openOfficialAccountChat`（小程序打开公众号会话）：同样要求同主体或关联主体（微信开放文档；社区汇总 2025-09 快照仅作参照）。
- 订阅号 1 天 1 群发、个人或企业主体均可注册；服务号企业认证主体、1 月 4 次、独有模板消息/订阅通知/客服消息（多来源交叉，2025 年快照）。
- 草稿箱/发布 API 依赖 access_token + IP 白名单：接入自动化时以微信公众平台开放文档当时现行版本为准，细节未验证。
- 个人订阅号的认证能力与年审费用以注册当时平台规则为准，未验证，注册前核对。

## 现状与可复用面（实测）

- 小程序已有 `pages/share/` 作品分享页、`saved_previews` 图库（TG 频道冷备份：三态落库 + `telegram_archive_log` 台账 + 分用户召回 CLI）、`milestones.py` 里程碑/连续打卡事件钩子——内容素材、事件源、幂等登记模式全部现成。
- `draw-portal/draw_portal/telegram_archive.py` 的 worker 形态（fire-and-forget、任务自带 Store 不绑全局、curl 子进程出网、任何失败只落日志不碰主链）是期 2 发布 worker 的直接模板。

## 引流飞轮与分期

**期 0（线下，不写码）**
- 注册订阅号，主体与小程序同主体；名称与小程序品牌统一（呼图机），注册时查重。
- 公众号后台绑定小程序；菜单「开始创作」跳小程序路径。

**期 1（人工运营，零后端改动）**
- 每周 1 篇精选图文：素材用自有样张、教学笔顺内容、已获授权的作品；文章插小程序卡片，短链/路径引导。
- 数据观察：关注转化、卡片点击，验证内容方向后再决定是否加投。

**期 2（自动化，动代码前须用户再拍板范围）**
- `saved_previews` 新增公开展示授权字段 + 产品开关（默认关）；`privacy-policy.md` 增「公开展示」条款。
- 精选标记 + 发布 worker：复用 TG worker 模式，走草稿箱 API，access_token 与 IP 白名单只配阿里云主节点。
- Quick Draw 数据集生成的作品公开发布带署名（QUICKDRAW-ATTRIBUTION.md）。

## 红线

- 肖像权：`sketch_render` 照片精修产物是用户照片的素描像，公开发布=公开肖像，必须逐作品显式授权，不做默认全量展示。
- 公众号任何对外内容不出现境外服务表述（TG 面仅内部运维，与对外内容面物理隔离）。
- 订阅号一天最多 1 群发，内容节奏按此排期，不承诺日更。
