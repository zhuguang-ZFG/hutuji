# 小派双端界面追加修复

用户明确两个界面均需改善：量产 Freenove 2.8 寸设备屏幕与小程序小派聊天页。接续三仓故障审查，保留现有设备控制、录音授权和账号边界；设备屏幕使用现有 LVGL 与程序表情，不增加图片资源。

## 已确认原因

- 设备分辨率 320×240，控制抽屉仍按 480×320 计算。四行至少 56px 的按钮加间距超过 240px；点动十字右侧六个工具键的宽度不足以容纳中文。
- 首页 96px 说话按钮、顶部可拖动入口与底部字幕互相争抢空间，保存的旧坐标会延续重叠。
- Freenove 未包含在显示文件的机器 HUD 条件编译中，状态点、坐标和步距反馈缺席。Kawaii 表情仅随情绪变化，未接入聆听与说话状态。
- 手动点动的新鲜坐标预检最长 6 秒，UI 与 MCP 入口都可能占住应用主循环。
- 小程序同时堆叠文字行、语音大按钮和版本页脚，聊天空间被压缩；缺少明确的待回复气泡与可操作的首屏引导。

## 实现与验收

1. 小屏首页固定底部入口，56px 触控高度；表情、字幕、顶部状态各占独立区域。大屏原有拖动位置保留，小屏不读取/覆盖旧布局 NVS。
2. 小屏控制抽屉保持 56px 按钮，通过主操作、点动、调试、连接分页容纳功能；不依赖缩小字体或不可达滚动。状态与错误来自现有 Job/Pipe。
3. 表情随真实聆听/说话切换细微反馈；复用现有定时器，保留任务高压期暂停约束。
4. MCP 和屏幕手动预检共享有界后台执行槽，拒绝重复排队；其余工具维持原主循环语义。错误 JSON 必须正确转义。
5. 小程序明确文字/语音输入切换、紧凑状态头、提示词入口与待回复反馈；录音按钮保持原生 touch 生命周期，切换输入方式不得启动录音或自动发送。

验收以真实源码布局/运行时截图、会话与并发回归、最终固件构建为准。编译、开发者工具、手机和实体屏幕分别记录；本地截图不等于已刷机。
