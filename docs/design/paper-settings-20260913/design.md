# 纸张设置实现设计

## 配置与边界

`PaperConfig` 是 Python 共享校验与序列化入口，设备侧用同字段的纯核心校验。字段使用毫米，最多一位小数：`paper`（A4/A3/A2/custom）、`width_mm`、`height_mm`、`landscape`、`margin_mm`、`swap_xy`、`max_x_mm`、`max_y_mm`。机器范围指从当前原点起已经核对的正向可绘制范围；不把无软限位机器的 `$130/$131` 当实测。

默认纸张 210×297、留边 10mm，沿用当前 190×277 撰写区。横竖版先确定纸张方向，再扣留边，最后由 XY 交换映射机器轴。画图的既有 5mm 构图内边距与文字的既有排版内边距保留，避免借新功能改变锁定画质参数。传入配置必须使完整撰写区落入设备范围。

S3 NVS 保存每台设备的配置及版本；`hutuji.paper` 读取/修改，`hutuji.status` 发布配置与能力。修改只在终态且 worker 已收敛时受理，读回确认后界面显示成功。配置增大行程需要显式的实测确认；设备屏幕修改纸张不隐含修改行程。

2026-09-14 跨仓对照修正：`status.paper` 已在 v0.5 表示有纸/无纸的遥测字符串，必须保留。新增配置使用 `status.paper_config = {schema: 1, config: {...}, marker: "p1:..."}`；字段在场但损坏须拒绝，不能降级为旧 A4。设备请求可达不等于写字机已就绪，发送与修改还须 `connected/ready` 为真。前段候选中 `status.paper` 配置对象的口径由此 supersede，尚未按旧候选发布。

Portal 通过当前绑定的精确 MAC 读写设备，保存最近一次合法读回供离线预览；缓存按设备及归属保存。每个生成事务只取一次快照，照片后续精修继续用原快照。云端工具使用调用设备 ID 解析配置；内部调用携带已经解析的快照，不让后台 worker 重新猜机型。

## 生成、文件与发送

`MachineProfile` 扩展撰写宽高，`WriteLayout` 与 `LaidOutPage` 携实际页尺寸，笔顺和表格不再引用固定页宽。vpype 全管线保留，动态布局发生在毫米容差处理之前；转置仍在弧拟合前完成，旋向与 I/J 从最终几何产生。

发现的前置缺陷：`pipeline._materialize_laid_pages` 连续执行两套转换循环，第二套未传 profile，覆盖第一套输出。先以真实转换回归修复，再接动态页尺寸。

配置快照与 G-code SHA-256 存入不公开下载的伴随元数据。`/files` 使用该文件的特定配置复核并返回配置标记，禁止用任意大包线或多个动态配置择一放行。保存/发布/OSS/TTL 清理一并保留或回收元数据。旧文件无元数据仍只接受既有两个固定档。

新 S3 在下载 G-code 时核对配置标记，配置不匹配在发送第一条运动前拒绝；无标记文件只允许默认配置。Portal 发送前也核对任务快照与明确目标，避免用户看到旧预览却用新设置。缓存、inflight、Redis payload 均包含完整配置与目标，取消仍只结束 waiter，不拆共享付费生成事务。

## 双端体验

小程序纸张设置展示纸面示意、有效尺寸、轴向映射与适配结果，保留手机号/登录/归属闸。创作、聊天和画板能看到当前纸张并进入设置。设备小屏采用分页设置，不挤压已有 56px 控件。

画板第二轮增加对称与放射笔迹、几何素材、逐笔回放；导出与实时渲染复用路径，保留白纸留白。切换纸张时保留旧草稿，用户选择适配后统一缩放到新画布；不让静默归一化改变手绘构图。

## 发布与回退

先完成软件、固件候选和真实布局验收，再从各仓明确提交发布。后端新增字段/元数据保持旧默认兼容；设备能力未就绪时新增设置不可用。配置 `HUTUJI_USAGE_INGEST_SECRET` 后，云端 draw/write/teach 会要求完整设备 MAC，必须先准备设备能力与角色提示，再安装 Portal 的 `/api/internal/paper[/push]`，最后切严格生成端，不能先部署新后端让旧调用失效。Redis payload 有配置快照和 claim 所有权，切换必须暂停入口、排空旧队列并停旧 worker。

主备配置与代码核 SHA，单主 bridge 不变；上传小程序与固件目录和实际设备升级分别记录。回退前先恢复默认纸张并核对当前无任务，不能使大幅产物绕过旧校验器。`scripts/auto_deploy.py` 的备份记录保留原服务清单及队列 URL 摘要，恢复内容校验失败时不启动混合版本。
