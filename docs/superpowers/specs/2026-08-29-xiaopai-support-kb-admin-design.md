# 小派售后知识库编辑后台（一期）设计

> 状态：**规格已批准；阿里云已 enable**（公网 `/kb-admin/`）。2026-08-30 发布幂等：「文档已存在」视为内容未变成功。京东云一期不跑。见 `kb-admin/README.md` 与 `docs/deployment.md` §kb-admin。  
> 日期：2026-08-29  
> 仓库：hutuji（枢纽仓；部署面 = 阿里云主节点）  
> 渠道锁定：只服务「对小派说话」的装机 / 故障 / 售后语音（不接微信客服、不做网页访客聊天）。

## 0. 决策摘要

| 决策点 | 选择 |
|---|---|
| 召回真源 | **小智官方云知识库**（现网 KB，agent `2094251` / 容器 id 以控制台为准） |
| 编辑真源 | **阿里云后台自有库**（一期新建） |
| 架构路线 | **A：阿里云 CMS → 发布时 `update-kb` 推小智**；不采用百炼/自建检索 + MCP 绕路 |
| 一期范围 | **FAQ 问答条目** CRUD + 同义问 + 草稿/发布 + 发布记录 + 现有 md 一次导入 |
| 内容量 | **先搭壳**：不卡条数；内容由售后人员陆续攒 |
| 二期（本期不做） | 排查流程（步骤树 / 分支）、转人工工单、企业 SSO |
| 固件 / 出图 | **零改动** xiaozhi / Grbl / `hutuji_draw` 主链 |

硬约束（禁止重开）：AI = 小智官方云 + MCP；阿里云只承载 MCP/bridge 与**本后台**，不替代小智对话大脑。

## 1. 问题与动机

### 1.1 现状

- 仓内 `docs/xiaozhi-agent/knowledge-base.md` ≈ 80KB / 785 行，已 sync 上小智 KB；小派角色已含「售后服务助手」口径。  
- 内容偏「契约 + 工具说明 + 奎享对照」，**装机/高频故障 FAQ 条数偏少**，且改稿依赖会 Git / 会跑 `xiaozhi_console.py sync|update-kb` 的人。  
- 售后人员没有可登录的编辑后台 → 知识迭代慢、易双源漂移。

### 1.2 目标（一期成功标准）

1. 售后人员用浏览器登录后，能对 FAQ **增删改查**、挂**同义问**、设**启用/停用**。  
2. 点「发布」后，小智侧 KB 文档被替换为本次发布快照；发布结果（成功/失败、md5、时间、操作者）可查。  
3. 可从现有 `knowledge-base.md` **一键拆条导入一次**作冷启动；之后日常只改后台。  
4. 不要求第一期凑满 N 条；空库或少条也可上线（壳可用即过）。

非目标：宣称「客服已完备 / 可出货」；真实语音全量 HIL 仍按 `release-readiness.md` 另项。

## 2. 真源与同步约定

```
[售后人员]
    │ 编辑草稿
    ▼
[阿里云后台库]  ←──── 编辑真源（一期唯一可写）
    │ 发布（拼装 markdown / 结构化正文）
    ▼
[小智云 KB]     ←──── 运行时召回真源（小派语音）
    │ 可选：发布成功后导出
    ▼
[仓内 knowledge-base.md 备份]  ← 只读备份，禁止日常手改与后台并行
```

- **禁止**：一边改仓内 md、一边改后台且两边都当真源。  
- **发布失败**：后台保留草稿与失败记录；小智侧保持上一成功版本（不半截覆盖——若上游 API 只能整文档替换，须先组完整正文再一次提交；失败则不调用或调用失败后明确告警）。  
- 控制台 JWT / 设备消息 token：**只存在服务器环境变量**，永不下发浏览器、不入库。

## 3. 信息架构（一期数据模型）

### 3.1 FAQ 条目

| 字段 | 说明 |
|---|---|
| `id` | 稳定 UUID |
| `title` | 列表标题 / 召回主问 |
| `body` | 标准答（Markdown 纯文本，一期够用） |
| `category` | 枚举：`install` \| `fault` \| `consumable` \| `safety` \| `kxnx` \| `other` |
| `aliases` | 同义问字符串列表（用户可能怎么说） |
| `enabled` | 停用条目不进入发布正文 |
| `updated_at` / `updated_by` | 审计用 |
| `sort_key` | 可选；发布时同分类内排序 |

### 3.2 发布记录

| 字段 | 说明 |
|---|---|
| `id` | 发布记录 UUID |
| `created_at` / `created_by` | 发起时间与操作者 |
| `status` | `success` \| `failed` |
| `xiaozhi_doc_md5` | 成功时上游或本地拼装正文 md5 |
| `error_summary` | 失败时脱敏摘要（无 token） |
| `faq_count` | 本次启用条数 |

### 3.3 发布正文拼装规则（钉死）

发布时由后台生成一份 Markdown（或小智 API 接受的等价结构），建议结构：

1. 固定前言（产品一句话 + 售后语气约束）——可配置，默认从现网 KB 头部摘一版。  
2. 按 `category` 分节；每条 = `### {title}` + aliases 一行提示 + `body`。  
3. **仅 `enabled=true`** 进入正文。  
4. 二期流程树未上线前，**不**把仓内长篇「工具契约」整段强行导入为可编辑 FAQ，除非人工勾选导入；避免员工误改 MCP 契约话术。

导入器：解析现有 `knowledge-base.md` 的 `##`/`###` 为候选条目，导入后标 `imported=true`，人工启用后才进发布。

## 4. 后台功能清单（一期）

| 模块 | 必须 | 说明 |
|---|---|---|
| 登录 | 是 | 少人售后：用户名密码或单邀请码；会话 cookie/JWT 本地即可 |
| FAQ 列表/编辑 | 是 | 表格 + 表单；分类筛选；启用开关 |
| 同义问编辑 | 是 | 多行文本或 tag 输入 |
| 草稿自动保存 | 建议 | 失焦或定时保存，防丢稿 |
| 发布 | 是 | 二次确认；调用服务端 `update-kb` 封装 |
| 发布记录 | 是 | 只读列表 |
| 从 md 导入 | 是 | 管理员一次性/可重复干跑预览后再写入 |
| 排查流程编辑 | **否** | 二期 |
| 角色权限细分 | **否** | 一期全员同等编辑权即可（可留 `role=admin` 字段） |
| 公网匿名访问 | **否** | 必须鉴权；安全组/nginx 限制 |

## 5. 部署与安全

- **宿主**：阿里云 `47.112.162.80`（与现役 MCP 同机或同机不同 unit）。  
- **进程**：独立 systemd unit（建议名 `hutuji-kb-admin`），venv 可共用或独立；**不得**把后台挂进公网无鉴权的 `/files` 旁路。  
- **入口**：独立子域或 path + Basic/登录墙；nginx 仅反代到 loopback 端口。  
- **密钥**：`XIAOZHI_CONSOLE_TOKEN`（或现有控制台 JWT 刷新脚本同源）只给该服务 `EnvironmentFile`；复用 `deploy/` 里 token 看门狗思路，文档写清「与设备消息 token 不是同一个」。  
- **日志**：复用 `hutuji_mcp/redact.py` 脱敏；禁止打完整 JWT/激活码。

## 6. 与现网脚本关系

- 发布路径优先封装现有 `scripts/xiaozhi_console.py` 的 `update-kb` / `sync` 能力为库函数或子进程，**禁止**再复制一套未脱敏的 HTTP 客户端。  
- 一期可不改小智 role-prompt；FAQ 发布只动知识库文档。  
- 设备侧 MCP 工具集不变。

## 7. 分期

| 期 | 交付 | 验收 |
|---|---|---|
| **一期**（本规格） | 登录 + FAQ CRUD + 同义问 + 导入 + 发布 + 发布记录 | 员工能改一条 FAQ 并发布；小智召回测 3 个问法命中（可用控制台 `recall`，不强制真机语音） |
| **二期** | 排查流程编辑器（步骤、分支、建议调用的设备工具提示） | 另开规格 |
| **明确不做** | 微信/网页客服入口、百炼检索 MCP、转人工、改出图链 | — |

## 8. 开放项（实施前可再定，不挡写计划）

1. 子域最终名：`kb.donglicao.com` vs path `/kb-admin`。  
2. DB：同机 SQLite（最快）vs Postgres（若已有）。默认建议 **SQLite + 定期备份**。  
3. 发布正文是否保留现网 KB 里「工具清单 / 禁止事项」固定附录（只读块，不进 FAQ 表）。默认建议 **保留为可配置只读附录**，防契约被误删。

## 9. 非目标与禁语

- 不宣称「售后知识库已完备」「可出货」「联调完成」。  
- 不重开「G-code 在设备端生成」或「不用小智云改自建对话大脑」。  
- 本规格批准 ≠ 已部署；部署与门禁按既有 `deployment.md` / `agent_gate` 纪律另批执行。
