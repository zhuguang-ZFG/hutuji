# 出货总路线图设计（小程序 + 图生图 + 控机）

> 状态：规格已批准（2026-09-08；用户确认「认可」方案 C）。  
> 日期：2026-09-08  
> 仓库：hutuji（枢纽）+ draw-portal/weapp + xiaozhi 设备侧（控机 HIL 涉及）  
> 用户主诉：小程序简陋；图生图丑、不真实、无素描感、达不到艺术家标准；小程序还控制不了绘图写字机。

## 0. 决策摘要

| 决策点 | 选择 |
|---|---|
| 总排法 | **方案 C**：控机冒烟（短）→ 画质主里程碑 → 控机完整 HIL → 小程序去简陋 → 30 轮 → 合规 |
| 出货硬闸 | 原验收三条 + **图生图目视过关**（四项齐才算试产门槛） |
| 图生图题材 | **不限人像**（静物 / 风景 / 宠物等均可） |
| 目视验收 | **固定样张包回归 + 真机随手拍抽检**（两边都过） |
| 画质目标档 | **艺术家素描标准（笔式可画）**：结构线 + 排线/交叉排线表达体积与明暗，像手绘素描而不像上色本描边；单色；须过中心线描摹上纸且主题可辨、人像须能认出本人（2026-09-08 用户补强：「要达到艺术家素描的标准」；supersede 初稿「偏写实插画线稿」措辞） |
| 第一大刀 | **M0 冒烟通过后立刻开 M1（图生图画质）**；不把 M2/M3 塞进同一刀 |
| 与既有默认下一刀 | 屏幕五按钮 HIL、断连 `paper_active` abort、生产签核 **并入 M2/M4/M5**，不另开平行路线；不重做已有证据项（语音出图、页尾归位、换纸中 abort 等） |

**笔式边界（诚实）**：单笔绘图仪做不到石墨灰阶连续调；「艺术家素描」在本产品 = **矢量可描的素描语言**（轮廓 + 结构线 + 疏密排线），不是扫描照片、不是灰阶渲染。禁止用放宽 §5 / 纸面风险闸去「假装」像照片。

非目标：USB Host / CH9350 / 合并固件 / 设备端生成 G-code；把灰阶写实照片当目标；小程序视觉大改版挡 M1；未过硬闸时宣称可出货 / 联调完成。

## 1. 硬闸（试产门槛）

必须全部闭合，缺一不可：

1. **语音控制画图/写字 + 带记忆人机交互 + 小程序控制**（2026-09-06 用户基准；小程序形态已 supersede 为真微信小程序「动力巢」）。  
2. **连续 30 轮随机测试**：功能全程正常、无闪退无卡顿、常规室内环境无明显失灵。  
3. **小批量试产条件、符合销售要求**（含备案、隐私协议、签核纸面）。  
4. **图生图目视过关**（2026-09-08 增补）：  
   - 样张包回归通过；且  
   - 真机随手拍抽检通过；且  
   - 目标视觉档 = **艺术家素描（笔式可画）**：有结构与排线体积感；非上色本均匀单线描边；亦非灰阶照片糊描。

状态真值仍只写在 `docs/release-readiness.md`；本文件是路线与判据设计，不替代 readiness 勾选。

## 2. 里程碑

### M0 — 控机冒烟（≤0.5 天）

**目的**：确认「小程序 → 云 → 设备」今晚修复后的链路仍通，避免在断链上调画质。

**动作（最小集）**：

- 账号已绑定、设备在线（`hutuji.status`：connected / ready / authorized 口径以现网为准）。  
- 小程序推一张已有/新传图到设备预览上屏。  
- 控制页：读到 status；暂停 / 继续 / 停止各成功触发一次（有屏显或日志）。

**完成判据**：有本机/设备日志或屏显证据。不通 → **先修链路，不进入 M1**。

**非本里程碑**：点动全矩阵、体验改版、画质调参。

### M1 — 图生图画质（第一大刀）

**目的**：把照片→线稿拉到 **艺术家素描（笔式可画）** 档，并通过样张包 + 随手拍。

**样张包（建议，实施计划可微调文件名）**：约 5 张固定图——人像 ×2、静物、风景、宠物（或等价非人像一类）。落本机证据目录（如 `results/local-only/…`），**隐私原图不进 git**。

**随手拍抽检**：真机连续 **≥5** 张用户随手题材（题材不限），目视过关才算 M1 闭合。

**目视及格表（样张与随手拍共用）**：

1. **像主题**：人像能认出本人；非人像能一眼说出物体/场景。  
2. **素描语言**：可见结构线与排线疏密（体积/明暗用线表达），不是均匀描边上色本。  
3. **干净可画**：无明显灰阶糊团、水印字、脏噪点；纸面主题仍可辨（过描摹 + §5 后）。  
4. **艺术家观感**：你（产品方）愿意称之为「素描作品」而非「AI 描边」。

**技术面（设计边界，细节在 M1 实现计划展开）**：

- 主修：i2i 提示词（从现行「均匀单线条勾勒」升到素描排线语言）/ 通道选择与质量门（魔搭 vs TCB 谁胜出若不够素描则降权或关）/ 必要后处理；描摹与纸面风险闸复用，**不为「像照片」放宽 §5 或纸面闸**。  
- 禁止目标：灰阶明暗照片感、彩色、大块填充（下游糊成噪点或抬笔爆炸）。  
- 合规：隐私协议「照片传第三方 AI」仍为上架前置（属 M5，M1 不替代）。

**完成判据**：样张包按及格表过关 + ≥5 张随手拍过关；证据勾回 `release-readiness.md`。不过 → 不得宣称画质完成。

### M2 — 小程序控机完整

**目的**：兑现硬闸①中的「小程序控制」。

**动作清单（与现有控制页 / `hutuji.*` 白名单对齐）**：

- 点动四向、步距切换、抬笔/落笔、试笔、回原点。  
- 任务：暂停 / 继续 / 停止（abort）/ 重画。  
- 与设备屏上行为对账；换纸中 abort 保持诚实「无法即停」语义（契约 §4.1）。  
- 既有固件债并入：预览确认相关若仍堵控机主路径则本里程碑处理；断连 `paper_active` abort 复测可与 M4 合并，但若控机停止路径依赖它则本里程碑先做。

**完成判据**：上表动作真机全绿，有取证记录。

### M3 — 小程序去简陋

**目的**：主路径不再以「半成品」阻塞验收观感。

**范围（刻意收窄）**：

- 主路径：传图 →（Canny / i2i）双预览理解 → 推送设备 → 进入控机。  
- 空态、错误文案可读；绑定/配网失败可恢复。  
- **不做**：整站视觉大改版、营销落地页、与出货无关的功能堆叠。

**完成判据**：用户过一眼主路径，不再将「很简陋」列为试产阻塞（口头或 readiness 勾选即可）。

### M4 — 稳测（30 轮）

**目的**：硬闸②。

**范围**：随机覆盖语音画/写、传图/图生图、小程序控机、多页写字等；已知问题（如 TLS 连接复用未保活导致预览/页 2 延迟）按失败项修复后重跑。

**完成判据**：30 轮全程正常，无闪退无卡顿，常规室内无明显失灵；证据落盘。

### M5 — 合规与试产签核

**目的**：硬闸③。

**范围**：

- 微信小程序备案（改名「动力巢」）与审核上架前置。  
- 隐私协议补「照片传第三方 AI 服务（魔搭 + 腾讯云混元等）」条款。  
- 出货级纸面签核与销售/试产条件核对。

**完成判据**：平台与纸面签核材料齐；readiness 对应行可勾（仍禁止口头「可出货」无证据）。

## 3. 依赖与顺序

```
M0 冒烟 ──通过──► M1 画质 ──► M2 控机完整 ──► M3 去简陋 ──► M4 30轮 ──► M5 合规
     │
     └──失败──► 修链路（绑定 / messaging token / 推送自愈 / 设备在线）后重做 M0
```

- M1 可与「备案材料准备」人工并行，但 **代码第一刀仍是 M1**（在 M0 通过后）。  
- M3 不阻塞 M1 开工；若 M1 需要最小 UX（例如双版本预览切换）可开窄 PR，不算提前做完 M3。

## 5. 第一刀（批准后下一步）

1. 执行 **M0 控机冒烟**（真机，用户在场或异步回传结果）。  
2. M0 通过后，用 `writing-plans` 产出 **M1 实现计划**（提示词/通道/后处理/样张包路径/验收表），再动手改代码。  
3. 未写 M1 plan、未过 M0 前：不把「艺术家线稿」当已完成。

## 6. 明确不做（防膨胀）

- 重开已否决架构（双芯片合并、USB Host、CH9350、设备端 G-code）。  
- 为门禁绿改产品行为或放宽 §5 / 纸面风险闸来「假装」像照片。  
- 把 MCP 组 0–4、已闭环语音出图/换纸证据当待办重做。  
- 在 readiness 对应行未 ✅ 时宣称可出货、联调完成、硬件已验证。
